# TorrentLinker 1.0.0-beta.28

Cette bêta rétablit la recherche c411 par identifiant IMDb, corrige une cause probable
du gel de la Bibliothèque lors des analyses répétées et améliore la réactivité des
grandes listes.

## Recherche et Bibliothèque

- c411 ignore désormais un identifiant IMDb sans le préfixe `tt` et renvoie des
  sorties récentes sans rapport. TorrentLinker envoie maintenant `tt…` à c411 ; les
  autres indexeurs Torznab reçoivent toujours le numéro seul (#52).
- Après une recherche, chaque nouvelle analyse de la Bibliothèque restaurait les
  résultats précédents en parcourant toute la liste plusieurs fois par élément, sur
  le fil de l'interface. Avec 4 000 éléments, l'interface restait bloquée environ
  7 secondes ; c'est désormais moins d'une seconde. C'est une cause probable du gel
  signalé sous Windows (#51), pas encore confirmée sur l'ordinateur concerné.

## Téléchargements et chemins

- Correction d'une `KeyError` répétée dans l'affichage de la file après un envoi.
- La réserve d'espace supplémentaire devient facultative pour les nouvelles
  autorisations de téléchargement direct. Les réserves existantes sont conservées.
- Les lecteurs réseau Windows résolus en chemin UNC sont correctement traduits avant
  l'envoi vers un client Linux ou Docker (erreur Transmission « download directory
  path is not absolute »).
- Les résultats incertains d'un envoi interrompu sont mieux expliqués ; il faut
  toujours vérifier le client ou le tracker avant un nouvel envoi.

## Assistant et bureau

- Les relances s'appuient sur les actions réellement exécutées : une réponse
  précédente ne vaut plus preuve d'un envoi ou d'une vérification d'espace. Une
  réponse sans outil indique qu'aucune action n'a été effectuée.
- Plus de compaction inutile du contexte pour une nouvelle discussion.
- Correction d'une concurrence à la fermeture entre la base de l'assistant et une
  évaluation de fournisseur en cours.
- Le thème « Système » de l'AppImage suit de nouveau le thème sombre de GNOME.
- Davantage d'explications de diagnostic Upload traduites en français et en anglais.

## Réactivité et assistance

- Avec 12 000 torrents, le premier affichage passe de 1,93 s à 765 ms. Dans une file
  de 12 000 entrées, la sélection passe de 384 à 22 ms et une notification d'envoi
  de 1,58 s à 274 ms. La mise à jour d'un échange dans une discussion de 100 échanges
  passe de 825 à 28 ms. Mesures sur un poste Linux, sans garantie par plateforme.
- Nouveau rapport d'assistance téléchargeable depuis le bureau et le WebUI. Il exclut
  identifiants, adresses de serveurs, chemins privés, titres et conversations.
- Instructions de sauvegarde et de restauration, application arrêtée, en français et
  en anglais.
- En cas de blocage de l'interface, les diagnostics écrivent les piles des fils avant
  la reprise. Les tests des paquets incluent dix nouvelles analyses de Bibliothèque.

## Validation et limites

La suite complète passe avec 1 890 réussites et 148 tests optionnels ignorés. Les
mises à jour depuis 0.12.2 et beta.27 ont été vérifiées sur des données de test.
Le gel Windows n'est pas confirmé corrigé : merci aux personnes concernées de
retester avec cette version. L'audit de récupération et la validation des plateformes
se poursuivent. Cette version reste une bêta.

## English

This beta restores c411 searches by IMDb ID, fixes a likely cause of the Library
freeze on repeated scans and makes large lists more responsive.

- c411 now ignores an IMDb ID without its `tt` prefix and returns unrelated recent
  releases. TorrentLinker now sends `tt…` to c411; other Torznab indexers still
  receive the bare number (#52).
- After items had been searched, each rescan restored previous results by walking the
  whole Library several times per item on the GUI thread. At 4,000 items this blocked
  the interface for about 7 seconds; it now takes under one second. This is a likely
  cause of the reported Windows freeze (#51), not yet confirmed on the affected machine.
- Fixed a repeating queue-display `KeyError` after a successful send.
- Additional free-space reserve is opt-in for new direct-download grants; existing
  reserves are kept.
- Windows mapped drives that resolve to UNC paths are translated before being sent to
  a Linux or Docker Torrent Client.
- Uncertain outcomes after an interrupted send are explained more clearly; check the
  client or tracker before sending again.
- Follow-ups are grounded in recorded tool execution. Replies without tool calls say
  that no application action was performed.
- Fixed needless context compaction for fresh discussions and an Assistant shutdown
  race with in-flight provider assessments.
- The AppImage's System theme follows GNOME's dark theme again.
- More English/French Upload diagnostic explanations.
- With 12,000 torrents, first display fell from 1.93 s to 765 ms. In a 12,000-entry
  queue, selection fell from 384 to 22 ms and a send notification from 1.58 s to
  274 ms. Updating one run in a 100-run chat fell from 825 to 28 ms. These are Linux
  workstation measurements, not platform guarantees.
- New desktop and web support reports exclude credentials, server addresses, private
  paths, titles and conversations.
- English and French stopped-app backup and restore instructions.
- Stall diagnostics write thread stacks before the GUI recovers. Package smoke tests
  include ten Library rescans.

The full suite passed 1,890 tests with 148 optional skips. Upgrades from 0.12.2 and
beta.27 were verified on fixtures. The Windows freeze is not confirmed fixed; affected
users are asked to retest. Recovery auditing and platform validation continue. This is
a prerelease; the stable release remains 0.12.2.
